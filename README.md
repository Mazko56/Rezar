# REZAR Bot — ТЗ від 11.10.2026

Основа: надісланий користувачем `app1110.zip`. Усі тексти і кнопки перенесено з **«Вставлений текст markdown(5).md»**. У боті **немає сторонніх повідомлень** з попередніх версій на кшталт «Оберіть наступний крок у меню нижче», «Побажання збережено» чи «Контакт отримано».

## Сценарії

- `/start`: вступне повідомлення, через 2 секунди матеріали презентації (якщо завантажені), потім головне меню.
- `Підібрати авто`: привітання, марка й модель → рік → бюджет (6 кнопок під полем вводу, 3+3) → контакт → «в чаті / зателефонуйте» → результат з двома кнопками «аукціони / дилери».
- `Розрахувати під ключ`: вступний текст із ТЗ, перехід до **того самого** квізу.
- `Безкоштовні доступи до аукціонів`: 3 екрани з кнопками «назад / далі», після цього квіз або два варіанти доступів, якщо він завершений.
- `Чому авто з Кореї?`: 4 екрани з незмінним текстом, новий екран додається нижче в стрічці.
- `Зв’язок з менеджером`: кнопка «написати менеджеру», контакти, можливість написати запит і поділитися номером, без перекидання на аукціони.
- `меню`: перехід на головну. Синє меню Telegram налаштовується через `set_my_commands`.
- Прогрес квізу і відмітка про контакт зберігаються в `data/rezar.sqlite3` та відновлюються при повторному вході.

## Що не задано повністю у ТЗ

1. Медіа для мініпрезентації. Архів містив `assets/3.png`, але це насправді **HTML, а не PNG**. Через це він не може бути відправлений у Telegram як фото. Для презентації можна додати справжні `assets/presentation_circle.mp4`, `assets/presentation.txt` і `assets/presentation_video.mp4`. **Без файлів ніякий вигаданий текст-заглушка не надсилається.**
2. Посилання на Instagram, Facebook, сайт і офіс у ТЗ позначені словом «линк», але самих URL немає. Жодного вигаданого посилання не додано. Вказані в ТЗ посилання Telegram-каналу й чату використовуються.
3. Telegram API дозволяє одному повідомленню мати **лише один тип клавіатури**. Для гарантованої появи всіх шести варіантів бюджету використовуємо звичайну **нижню клавіатуру** (3+3), а в останньому ряду — «меню» і «менеджер». Це усуває попередню проблему з неуспішним редагуванням inline-кнопок. В інших розділах верхні inline-кнопки залишилися, як раніше.
4. Фото для нових екранів (поза вихідним комплектом `1.png`–`8.png`) не надані. Якщо фото відсутнє, надсилається лише текст із ТЗ.
5. Реалізація збору, а не відправлення заявки в CRM: інтеграції KeyCRM, Graspil, Railway PostgreSQL не додані, оскільки їхня схема і ключі відсутні в цьому ТЗ. Для збереження прогресу реалізовано SQLite (див. Railway Volume нижче).

## Медіафайли

Використані оригінальні `assets/*` з надісланого архіву. Відповідність файлів і нових екранів — `assets/README.txt`.

## Запуск

```bash
python -m pip install -r requirements.txt
```

У `.env` (не публікувати) додати `BOT_TOKEN`, ключі до аукціонів — змінними середовища. Запустити:

```bash
python -m app.main
```

## Екран **до** натискання Start

Текст зі стартового блоку ТЗ ставиться ботом через Telegram API `setMyDescription` під час запуску. Для зображення перед Start потрібно встановити **Description Picture / Intro media** у BotFather; локальний `assets/1.png` сам по собі цей екран не змінить. До першого `/start` бот не може відправити повідомлення в чат. Щоб побачити intro, відкрийте бот з нового акаунта / без активного чату.

## Дані

У `data/rezar.sqlite3` зберігається телефон і анкета. Для Railway потрібно підключити постійний **Volume**, інакше SQLite-файл на диску сервісу може зникнути після redeploy. Тому перед робочим запуском треба налаштувати Volume згідно `RAILWAY.md`.
